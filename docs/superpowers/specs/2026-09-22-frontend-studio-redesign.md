# AlignSpace 前端整体美化设计规格

日期：2026-09-22。状态：设计草案，待用户审阅；不代表实施已开始。

## 1. 已确认方向

- 采用样图①「建筑设计工作室风」：暖白、炭灰、橄榄绿，大幅图片和留白。
- 全站统一美化，保留现有业务、权限和后端接口。
- 项目工作区拆为五个导航页面：项目概览、灵感与偏好、设计协商、空间方案、方案审批。
- 电脑端优先；手机端支持账户、项目查看、偏好确认与审批，复杂空间编辑优先适配电脑。
- 样图中的聊天、收藏、在线状态等不是新增功能要求。

## 2. 视觉体系

背景暖白 #F6F3EC，卡片 #FFFDF8，正文炭灰 #292B25，强调色橄榄绿 #565D3D，分隔线 #DDD8CD。状态颜色独立，错误不能只用橄榄绿表示。

主标题可用本机宋体/衬线字体呈现编辑感；正文、表单、数据和按钮使用系统无衬线字体。正文默认 16px，辅助文字不小于 12px。颜色最终按普通文本至少 4.5:1 对比度校验，不能仅凭色值认定合格。

桌面采用约 224px 左侧导航，内容区宽度随视口适配；空间编辑页使用更宽画布。采用 8px 间距体系、细边框和轻微圆角，避免大量阴影、渐变和装饰动画。参考图优先等比展示，缩略裁切可用于卡片，但查看原图不得裁切。

不使用样图中的示例人物、假数据或生成卧室图冒充用户项目内容。无图片时使用明确空状态，不自动添加演示数据。优先系统字体和现有资源，不新增外部字体、统计或云端依赖。

## 3. 页面与现有能力对应

| 页面 | 内容与动作 |
| --- | --- |
| 登录注册 | 保留邮箱密码注册、登录、会话恢复、退出及现有限制提示；使用统一品牌与表单样式 |
| 我的项目 | 项目列表、创建、项目码加入；SGD 固定币种、用户填写预算；角色按项目显示 |
| 项目概览 | 项目信息、已有成员信息、阶段、待办和对应页面入口；项目码动作保留原有角色权限 |
| 灵感与偏好 | 图片上传与删除、PreferenceBoard 分析及候选确认、已有偏好查看/修改、备用结构化访谈、未提交回答保留 |
| 设计协商 | 设计师反馈、约束新增/编辑/撤销、冲突与处理决定、等待另一方提示；屋主和设计师可用动作保持原权限 |
| 空间方案 | SpaceBoard 的房间/对象编辑、2D/3D、BindingPanel 材质绑定与复核、同步状态、版本与冲突提示 |
| 方案审批 | 说明书目标编辑、重新生成、现有 BriefDetail 阅读/历史/导出能力、现有审批与联合审批状态；保持版本、哈希和过时保护 |

联合审批 UI 可从空间组件抽取为共用组件供审批页使用，不重复实现审批规则。页面阶段用于解释真实状态，不虚构顺序进度或未经后端支持的完成百分比。

## 4. 导航、角色与响应式

复用现有 URL 路由机制，在项目地址中编码当前页面；支持刷新、前进后退和直接进入页面，旧项目/说明书地址继续有效。具体参数形式在实施计划中按现有路由代码确定，不另建并行路由系统。

桌面固定左导航、顶部项目与角色信息。右侧辅助栏只在内容需要时出现，不强迫所有页面采用三栏。概览待办点击后进入实际任务所在页面，不能只跳到工作区顶部。

建议断点：1024px 起桌面布局；768–1023px 收起辅助栏、导航可折叠；767px 以下使用单列和菜单抽屉。320px 宽度应无页面级横向溢出，表格与空间画布可在自身区域滚动。触控目标至少 44px。

手机显示空间摘要与版本，明确提示复杂编辑建议电脑操作；不靠隐藏按钮替代后端权限。手机审批前须能查看实际说明书和空间摘要，不隐藏过时状态或待复核绑定。

## 5. 状态与数据保护

本次是前端重排，不改认证、刷新令牌、幂等、乐观版本校验、审批失效和三维同步规则。

项目级数据加载、会话和版本刷新由稳定的容器持有。拆页不能让各页面分别维护互相竞争的项目状态。通过拆分展示组件降低 Workspace 体积，但不做无关重构。

切页保留未提交表单；无法保留的编辑必须在离开前明确确认。三维同步进行中、409 草稿和待处理冲突不得因导航静默丢失；不能直接卸载 SpaceBoard 而丢弃内存草稿。原有说明书离开保护继续有效。

各页必须有加载、空、失败和权限状态。成功、等待、过时、冲突都以文字说明，不只靠颜色。分析为模拟、模型未配置、分析失败和不支持材质/铺法的提示继续可见，不伪装成真实 AI 能力已验证。

## 6. 可访问性

保持输入标签、语义标题与按钮；支持键盘导航和清晰焦点。移动菜单有可访问名称、展开状态与正确焦点管理。隐藏页面不能留下可聚焦控件或让读屏重复读取隐藏内容。尊重减少动态效果设置。

## 7. 实施与验证边界

后续先编写实施计划，再修改代码。实施顺序建议：公共视觉与壳层、账户与项目页、五页拆分、空间/审批适配、响应式和回归验收。

已有 6 个未提交文件必须保留；其中 App.tsx、App.test.tsx 与浏览器测试可能与本次重排交叉，实施前检查实际 diff，不能覆盖或将他人改动擅自纳入提交。不假设当前分支已经合并。

验收包括前端全测试、TypeScript 与生产构建、既有浏览器流程，以及新增导航/刷新/角色/草稿保留测试。重点回归：预算与密码契约、图片分析候选确认、约束协商、空间保存重载、409 恢复、联合审批与修改后失效。

浏览器视觉检查覆盖登录、项目列表及五页，在桌面约 1440px、平板约 820px、手机约 390px，并检查 320px 溢出。检查真实内容和空/错误状态；不能只以静态样图或测试数量宣称完成。

本轮不新增聊天、收藏、通知后台、角色体系、自动建模、模型供应商能力或云部署；不调用外部付费模型。后端和真实 DeepSeek 验收独立于视觉改造。
