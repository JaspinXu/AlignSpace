# 设计说明书独立只读详情页：设计规格

## 1. 目标与已确认范围

基线：主仓库 `/Users/shawn_chen/Documents/GitHub/Design_Inspiration_Agents`，本地 `shawn` @ `e31d23b`。

让屋主与设计师可以完整阅读某一份确定版本的设计说明书，并切换历史版本。用户已确认：独立详情页；本轮只读；编辑、重新生成和审批继续留在工作区。

不包含：导出、版本差异比较、真实模型、空间可视化、云部署、审批历史存储改造或说明书生成规则改造。

## 2. 现有代码与复用策略

- `frontend/src/App.tsx` 已使用 `?project=<id>` 导航，处理登录恢复和浏览器前进后退。
- `GET /v1/projects/{id}/state` 返回 `projectState.briefVersions` 与 `approvals`；每个版本已有 `version/contentHash/completeness/payload`。
- 当前说明书接口仅提供 latest 读取、版本编辑和审批；本轮复用项目状态接口，不为阅读新增后端 API。
- `frontend/src/workflow/Workspace.tsx` 保留所有写操作，增加查看说明书入口。
- 详情页读取时不启动分析、不生成新版本、不清除过时标志、不更新审批。

## 3. 导航

沿用查询参数，不新增路由库：

- 工作区：`?project=<id>`。
- 指定说明书：`?project=<id>&view=brief&version=<正整数>`。
- 工作区入口仅在存在说明书时显示，指向当时最新版本。
- `view=brief` 未指定版本时，加载成功后选择最新版本并以 replaceState 固定版本 URL。
- 版本切换使用 pushState，浏览器后退/前进能恢复选定版本。
- 明确指定的非法或不存在版本显示错误及返回入口，不静默替换成最新版。
- 项目没有说明书时显示“尚未生成设计说明书”，不创建说明书。
- 返回工作区移除 view/version；返回项目列表同时清理全部相关参数。
- 登录恢复后保留合法深链接。退出清空敏感页面数据和项目导航；未授权用户不能查看正文。
- 工作区有未保存输入时，进入详情页需确认离开或取消；不承诺跨页面持久保存草稿，不因用户点击阅读而静默丢弃输入。

## 4. 页面结构

顶部：返回工作区、版本选择器、版本号、内容哈希、最新/历史标签。

正文按顺序展示：

1. 项目概况：仅使用快照中能可靠确认的项目字段；项目 ID 必须与当前路由一致。
2. 设计目标：使用该版本 goals，按列表展示。
3. 偏好与来源：部位、维度、取值、状态、证据类型与来源 ID。已确认偏好和未确认观察明确区分，不能将所有 attributes 称为“已确认偏好”。
4. 设计师约束：展示快照实际保存的作用对象、类别、内容、理由、严重程度等字段。
5. 冲突：展示快照中的冲突状态、说明与解决结论，不从当前状态补写。
6. 未决事项：展示 unresolvedDecisions，避免空值被解释为已经确认。
7. 版本完整度及审批信息，按下节规则呈现。

缺失字段显示“未记录”，合法空列表显示“此版本未记录相关内容”，不生成推测内容。未知状态使用安全文字回退，不让整个页面崩溃。

所有用户内容按文本渲染，不使用未经清洗的 HTML。中文标签统一，长文本和移动屏幕不横向溢出；版本选择器具备可访问名称。

## 5. 快照与当前信息必须分离

### 正文不可变

正文只来自选定 `BriefVersion.payload`；完整度使用该版本的 `completeness`。禁止把当前 state.attributes/constraints/conflicts 拼进历史正文，禁止使用当前项目状态覆盖快照状态。

现有生成逻辑从示例模板起步，部分 project 字段未由真实项目信息覆盖。实现时核对 `application/briefing.py` 与模板：未证明由真实数据生成的示例名称、预算或其他字段，不作为真实项目事实展示。必要信息显示“未记录”，不借详情页扩展生成器修改范围。当前项目上下文若展示，必须单独标注“当前项目信息，非本版本快照”。

来源图片以快照 evidence.sourceId 为依据。第一版展示来源 ID，不要求加载缩略图；不能用当前新图片替代原图证据。历史版本缺少原始文件名时，不伪造名称。

### 审批是独立状态，不修改 payload

现有生成器将 payload.approvals 初始化为空，后续审批位于 state.approvals。详情页从当前仍保留的记录中，按 **briefVersion 和 contentHash 同时匹配**，展示角色、时间等信息；不改写快照。

当前系统会在需求改变或生成新版本时清除有效审批，因此不能把“找不到历史审批”显示成“从未批准”：

- 最新且未过时版本：显示当前有效审批情况，例如“屋主已批准／设计师尚未批准”。
- 最新但已过时版本：明确显示“方案已过时，原审批不再有效，请返回工作区重新生成”；无效的旧记录不计为当前批准。
- 历史版本：有匹配记录则显示“现存审批记录”；没有则显示“历史审批记录不可用，无法据此判断当时是否批准”。
- 快照里的项目状态只是生成时状态，不作为版本当前批准状态。

历史审批持久留档属于未来独立工作，本轮不做迁移、不通过猜测审计事件补齐。

## 6. 数据加载和错误处理

- 复用 ApiClient 的认证恢复、401 与退出通知，不另建令牌机制。
- 初次加载、刷新页面、版本切换、返回窗口焦点时获取状态；提供手动刷新，不新增后台轮询。
- 更新最新版本号、briefStale 和审批状态时，保持用户选定版本不变；出现新版本只提示“已有更新版本”，由用户主动切换。
- 快速切换项目或版本时，取消或忽略旧请求；旧响应不得覆盖新选中页面，退出后不得重新展示内容。
- 网络失败显示重试；保留同一版本已加载正文时明确标记“状态更新失败，审批状态可能不是最新”，不能伪装为已刷新。
- 403/404 不泄漏其他项目内容；切换项目或退出时清除旧正文。加载、空状态、错误状态都保留合理返回入口。
- 畸形 payload 显示可理解的读取错误；不要为了兼容而把当前共享状态当作快照补齐。

## 7. 组件与文件边界

- `frontend/src/briefs/BriefDetail.tsx`：数据加载、版本选择、只读详情布局。
- `frontend/src/briefs/briefPresentation.ts`：将未知 payload 安全转换为显示结构，集中处理字段缺失、标签与审批匹配。
- `frontend/src/App.tsx`：扩展查询参数导航与详情页入口分流。
- `frontend/src/workflow/Workspace.tsx`：阅读入口、未保存输入离开确认；保留现有编辑与审批行为。
- 对应新增详情页和显示转换单测，扩展 App 导航测试；样式保持现有设计体系。

本轮不大幅拆分 Workspace，不引入新前端框架或后端存储。

## 8. 验收标准

- 两个真实账户分别能从工作区进入详情、刷新指定版本、切换版本、前进后退及返回工作区。
- 创建 v1 后修改偏好/约束并生成 v2；查看 v1 的正文仍逐项对应 v1.payload，v2 对应 v2.payload。
- 历史记录缺失时不宣称未批准；当前审批必须同时匹配版本和哈希，过时提示正确。
- 详情页不出现编辑、重新生成、批准按钮；仅浏览不改变项目版本、快照哈希、审批或审计写事件。
- 页面不把模板残留、未确认观察或完整度指标描述为真实设计结论或双方一致率。
- 深链接不存在版本、空项目、无权限、会话失效、网络失败、快速切换和恶意文本都有测试。
- 未保存工作区输入可以取消离开，确认离开才导航；已有 409 输入保留与审批保护不回退。
- 后端全套、前端单测、构建、Ruff 及扩展浏览器套件通过；使用独立测试数据，不调用外部模型。
