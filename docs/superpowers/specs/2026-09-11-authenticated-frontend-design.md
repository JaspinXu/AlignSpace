# AlignSpace：真实账户与前端 MVP 设计

日期：2026-09-11
状态：用户已确认，进入实施。

## 1. 已确认的需求

- 前端使用 React、TypeScript、Vite，连接现有 FastAPI、LangGraph 和 SQLite 后端。
- 项目自己管理账户，第一版支持邮箱密码注册、登录、退出。
- 本阶段不提供邮箱验证、密码找回和邮件服务。
- 屋主创建项目，设计师注册登录后使用项目码加入。
- 保留五个 Agent 的现有协作流程，不加入装修效果图生成。
- 继续本地开发，GitHub 上传和部署另行处理。

## 2. 实现路径与选择

本设计采用独立 React 前端配合现有 FastAPI：网页负责表单和展示，后端负责身份、项目权限、状态和工作流。这样能够继续复用后端，并支持两个真实账户分别操作同一项目。

另外两种可行路径是 FastAPI 服务端模板页面，以及引入全栈 React 框架。前者工程结构较简单，但多步骤交互和共享状态展示需要更多手工组织；后者增加服务端渲染能力，也增加一个服务端运行层。本阶段采用已经确认的 Vite 方案。

## 3. 账户与会话

账户保存内部用户 ID、规范化邮箱、密码哈希和创建时间。邮箱按去除两端空白并转小写处理；数据库唯一约束防止并发重复注册。使用 Argon2id 保存密码哈希，密码按原文处理，不去除空白；建议长度范围为 15–128 字符，不要求特定字符组合。

注册成功后建立会话并进入项目列表。登录失败统一提示邮箱或密码不正确。界面明确邮箱尚未验证，不能把邮箱当作已核验的身份凭证。

采用短期访问 JWT 与可撤销刷新会话。访问令牌仅放在页面内存中，刷新令牌放入 HttpOnly Cookie；服务端只保存刷新令牌的哈希。JWT 包含用户 ID、会话 ID、签发方、接收方和有效期，使用固定允许算法验证。项目角色从数据库成员关系取得。

建议访问令牌有效期 15 分钟，会话最长 7 天。刷新令牌轮换并以事务处理；前端合并并发刷新请求，多标签页协调刷新，避免重复轮换。旧令牌重用使对应会话失效。

退出时服务端撤销当前会话并清除 Cookie；受保护请求同时检查会话有效性，因此已有访问令牌也不能继续用于该会话。页面刷新时通过刷新接口恢复登录。密钥缺失时正式认证服务拒绝启动，不使用内置默认密钥。

浏览器同源访问 API：本地由 Vite 代理 `/v1` 到 FastAPI。Cookie 限定认证路径，设置 SameSite；HTTPS 环境启用 Secure，本地 HTTP 开发使用显式开发配置。认证写操作校验允许的 Origin，防止跨站请求。登录、注册和加入项目接口采用服务端限流；日志不包含密码、原始令牌或项目码。

## 4. 项目成员与项目码

角色属于项目，不属于全局账户：创建者在当前项目是屋主，使用项目码加入的另一账户是设计师。第一版每个项目一名屋主、一名设计师。

创建项目只需要项目信息与图片处理同意，不再要求 `designerId`。尚未有设计师时显示“等待设计师加入”，允许屋主完成已有的偏好收集流程；最终审批仍需要两个不同账户。

屋主主动生成项目码。建议使用 12 位无歧义随机字符、24 小时有效、只能成功使用一次；数据库只保存摘要。生成时显示一次完整码，之后可以重新生成，新码立即撤销旧码。项目码通过用户自行分享。

加入操作要求登录，在单个事务中验证有效期、项目名额和账户不是屋主，再创建设计师成员关系并消耗项目码。并发兑换只能成功一次。无效、过期或已使用的码统一提示不可用；同一设计师重复加入返回已有成员结果。第一版不支持更换设计师。

未加入者不能通过项目码查询接口预览项目资料。服务端对每个项目操作重新检查成员关系，前端隐藏按钮仅用于交互展示。

## 5. 页面与模块

前端目录为 `frontend/`，按账户、项目、工作流和共享 API 客户端分模块。第一版界面文案默认中文，Agent 返回的原始内容保持原样；保留可集中替换的界面文案。

1. 注册与登录：邮箱、密码、确认密码、校验反馈和提交状态。
2. 我的项目：只列出本人参与的项目，显示项目角色与当前进度；提供创建项目、输入项目码加入和退出入口。
3. 项目工作区：顶部显示项目、本人角色、当前状态；主区域展示当前任务，侧栏展示偏好、约束、冲突和审批摘要。
4. 屋主任务：登记演示样本、明确同意处理、启动分析、回答广泛问题和细化问题、确认/修改/拒绝偏好，以及显式新增偏好。
5. 设计师任务：查看共享状态、提交当前后端支持的约束反馈、查看待处理冲突。
6. 对齐与方案：呈现冲突、提交现有接口支持的解决选项、查看和编辑 Design Brief、分别批准同一版本。

页面只展示后端当前支持的动作和选项，不能把未实现的自由问答或约束理解能力包装成可用功能。创建表单以实际 API 支持的房间类型和预算区间为基础；首版不增加尚无存储字段的房屋尺寸或工期表单。

状态必须同时用文本和视觉样式表达；输入有标签，键盘可操作，加载与错误反馈可被辅助技术读取。移动设备将侧栏移至主内容下方。

## 6. 共享状态与错误处理

后端是项目状态的唯一权威来源。登录后加载项目列表，进入工作区获取完整状态和当前任务；刷新页面能恢复同一任务。成员角色和可操作范围由服务端数据决定。

保留写请求的 `idempotencyKey` 和 `expectedStateVersion`。一次提交及其网络重试使用同一个键和相同请求体；用户修改内容后创建新键。409 版本冲突时刷新状态并保留用户输入，提示检查后重新提交，不自动覆盖另一人的修改。

窗口重新聚焦时刷新状态；等待另一方操作时每 5 秒读取一次，隐藏页面暂停轮询。第一版不引入 WebSocket。401 尝试恢复会话一次，失败后进入登录页；403 显示无权限；网络异常提供重试。

方案编辑后由后端产生新版本并使旧审批失效，界面展示这一结果。审批请求绑定用户当前看到的版本与内容哈希；数据变化时要求重新阅读对应版本。

## 7. 后端改动范围

- 增加用户、刷新会话、限流记录和项目码存储，以及可重复执行的数据库迁移。
- 增加 `/v1/auth/register`、`login`、`refresh`、`logout`、`me` 接口。
- 用验证后的账户与项目成员关系替代生产 API 中的 `X-Actor-Id`、`X-Actor-Role` 身份入口。自动化测试使用独立依赖注入，不暴露可通过请求切换的模拟认证。
- 增加 `GET /v1/projects`，限制为当前用户成员项目。
- 调整项目创建协议，允许尚无设计师成员。
- 增加 `POST /v1/projects/{projectId}/join-code` 和 `POST /v1/projects/join`。
- 增加 `GET /v1/projects/{projectId}/state`，返回完整共享状态、当前任务及当前成员角色；沿用已有授权逻辑。
- 检查偏好、约束、项目删除、样本管理和审批等写接口，明确并执行各自的项目角色权限。

旧开发数据库中的模拟成员不能自动绑定到同邮箱或相似 ID 的真实账户。本阶段保留旧数据库文件，以新的开发数据库运行真实账户演示；如需迁移旧项目所有权，再明确指定映射。

## 8. 当前能力边界

现有 Vision provider 返回固定观察，图片接口只登记 `fixtureId`，不接收图片文件。本阶段保留样本登记方式，并明确标为“演示样本 / 模拟分析”。没有实际图片资源时使用带名称的样本卡，不伪造照片或图像证据。

真实图片上传、对象存储、真实多模态 LLM 与任意自然语言约束解析是后续后端集成工作。真实账户本身并不意味着这些能力已实现。

不做邮件验证和密码找回意味着用户无法在产品内恢复忘记的密码；注册时清楚告知并允许使用密码管理器。账户只用于本地试用，正式对外开放前另行评估账户恢复需求。

## 9. 验证与交付

后端验证覆盖重复注册、错误密码、令牌验证、刷新轮换、退出即时失效、认证限流、旧身份头无法冒充、跨项目访问拒绝，以及项目码过期、撤销与并发兑换。

前端验证覆盖注册登录、会话恢复、提交错误、版本冲突和角色动作。端到端用两个隔离浏览器账户完成：屋主创建项目 → 设计师输入项目码 → 演示样本分析 → 问答与状态修订 → 冲突处理 → 同版本双人审批 → 退出后访问拒绝。

交付包括前后端代码、迁移、配置示例、本地运行说明和自动化测试。实现分三个连续步骤：真实认证与项目加入后端；前端账户和工作区；双账户流程联调。设计确认后编写对应实施计划。
