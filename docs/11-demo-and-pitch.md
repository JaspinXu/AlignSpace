# Demo and Pitch

## Current release boundaries (13 September)

The deployed flow uses model-backed reference-note understanding and a deterministic interview/state engine. The current competition gateway failed an image-input probe; do not demonstrate notes as if they were pixel analysis. Use uploaded permitted images for human review and source display. The vision adapter is available but disabled. Separate browser sessions are required for the two roles. Owner-operated testing is not independent user validation.

The five-minute pitch below is a narrative draft, not the official video length. The submission briefing says 30 minutes, with interpretation still pending.

## Core story

**Before:** ten beautiful images, three ambiguous adjectives, two people who think they agree.  
**After:** one brief showing what is liked, constrained, unresolved, and approved.

## Suggested five-minute pitch

Adapt when organiser rules are confirmed.

### 0:00–0:35 Problem

“A reference image does not say whether the homeowner likes the oak, lighting, layout, or whole room. Designers decode that manually. When the same word means different things, the misunderstanding appears later as another revision.”

### 0:35–0:55 Promise

“AlignSpace turns 3–10 references into a shared, evidence-backed living-room brief through a two-sided agent workflow. It helps both sides reach explicit, traceable agreement.”

### 0:55–2:50 Demo

1. Upload three consented references.
2. Show source-linked tentative attributes; correct one error.
3. Answer an adaptive lighting-conflict question.
4. Designer adds a maintenance/budget constraint.
5. Alignment Agent creates a neutral conflict.
6. Resolve and view updated brief.
7. Demonstrate dual approval and invalidation after edit.

### 2:50–3:35 Why agents

The model proposes note-derived evidence; the deterministic interview chooses questions; designers enter constraints; the state engine checks conflicts and approvals. Distinguish real model runs from rule-based coordination messages.

### 3:35–4:20 Readiness

Show Lightsail deployment, project-scoped image access, request budgets, manual fallback and professional-review blockers. Deletion automation and a dedicated kill-switch UI are not implemented.

### 4:20–4:50 Evidence

Show measured results with sample size. If incomplete, show evaluation design and label targets. Connect to SME intake/rework.

### 4:50–5:00 Close

“AlignSpace makes visual taste discussable, disagreement visible, and approval explicit—so designers spend more time designing and less time guessing.”

## Demo dataset

Synthetic “Project Haven,” using licensed/project-created images. Seed: pale oak + concealed storage; one cool-lit reference; luxury look within mid budget; light upholstery vs household with pet. No real name, home, budget, face, or contact.

## Reliability

Pre-warm and check quota; backup read-only video; deterministic cached run labelled as recorded; manual tagging; scoped reset; three consecutive rehearsals.

## Judge Q&A

**Why multiple agents?** Separate least-privilege roles, typed outputs, targeted tests, independent review, visible state, bounded recovery, and adaptive action.

**Hallucination control?** Proposals link evidence, expose confidence, pass gates, require confirmation; professional claims escalate.

**Business benefit?** Hypothesis: lower intake/rework. Measure time, agreement, corrections, revisions—not untested savings.

**Training data?** Foundation models plus orchestration. No general training on project data by default. Lawful evaluation assets.

**SME readiness?** Single-instance Lightsail, project-scoped sessions, observable model calls, manual fallback, narrow pilot, no deep integration.

**Disagreement?** Preserve both positions; humans decide; unresolved items stay visible.
