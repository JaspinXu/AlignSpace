# 有来源的设计讨论：本次改造

## 取舍

微信讨论指出的核心问题成立：原来 12 条人工组合的方案既不是实际案例，也不能构成偏好匹配的训练或验证数据。给它们换上更多风格名称，或放进向量库，并不能解决依据问题。

本次删除这些方案，改为“用户确认的独立需求 → 本地检索 → 展示原文与出处 → 设计师判断 → 双方确认简报”。支持“不限定风格”，保留颜色、材质、照明、活动、布局及维护等维度。图库中的新加坡案例仍作为独立的灵感入口。

## 两个来源各做什么

- [Atelier 手册](https://github.com/MickeyBadBad/atelier-mcp/tree/b21325782089bb26bbc0ff96204d4602264f86ea/docs/handbook)：采用 7 章住宅风格和材质、照明两章中的 22 段内容。仅选择 Anchor description、材质 In、暖冷色/色彩邻接、四层照明模型。保留上游引用、章节行号、提交版本和文件 SHA-256。它是二手资料；“存在引用”不代表原始书籍、项目或数值已经逐一核实。没有引入其 MCP、Blender、采购工具、代理或建筑规范执行逻辑。
- [Getty AAT 官方说明](https://www.getty.edu/research/tools/vocabularies/aat/about.html)：适合术语标识、同义词和层级关系，不能直接证明用户喜欢某种风格。先接入已核实的 [wood (plant material), 300011914](https://www.getty.edu/vow/AATFullDisplay?find=wood&logic=AND&note=&subjectid=300011914)，保留 Getty 名称、ODC-By 署名和核实日期。本地橡木/胡桃木值关联到上位木材概念，不声称完全等价。当前不是完整 AAT 数据库，也没有给 Japandi 等产品标签伪造 AAT ID。

## 当前实现

`app/knowledge.py` 使用 BM25 词法检索，少量中英查询扩展，最多返回 3 个不同章节来源。查询扩展是项目维护的检索辅助，不能当作权威风格定义或自动偏好映射。直接卡片仅以已确认的需求检索，避免把目标中的否定句、假设或模糊表达当成偏好。无词项命中时返回空结果；没有预设方案兜底。

禁用项和未撤回的设计师冲突值会先过滤来源，再排序。过滤采用显式词项和维护的别名，较保守：一段中即使只是顺带提到禁用材质，也会被隐藏；自由文本语义、跨语言否定范围尚不能完全理解。实际偏好确认仍经过原有约束验证。

笔记模型会检索最多 3 段、7,000 字符的参考上下文。系统提示明确要求把参考当作不可信数据，不能遵循其中命令，不能用手册替代用户证据。输出仍受原有 schema、用户引用 ID、待确认状态和角色约束限制。分析记录保存语料哈希和检索片段 ID；没有新加付费 embedding 服务或运行时外部检索。

卡片展示原文、来源、相关检索维度和未评估项，不再显示伪匹配百分比或没有报价依据的预算。预算保留在用户简报中，来源的成本状态为未知。进度条表示确认维度覆盖率；访谈的问题排序使用选项熵启发式，不能再解释为真实候选空间的信息增益。

导出 JSON 包含原文引用快照和 Getty 关联信息，全部参与内容哈希。审批本身不会刷新语料；两人只有批准相同内容哈希才算完成。后续内容编辑清除审批，并重新检索。旧项目在下一次编辑时获得新来源；读取旧项目不会把历史示例包装成真实证据。

## 维护与验证

运行 `python scripts/import_handbook.py` 可从固定提交重新构建选定片段，并保留 MIT 许可证。运行时数据位于 `app/knowledge_data/`，随现有 Docker 的 `COPY app` 一起部署。换版本需要维护者审阅选定段落、文件哈希、适用范围和许可证，运行测试后重启服务；语料缓存在进程中。不要在请求处理期间自动拉取上游。

新增回归覆盖：空查询/无依据弃答、中英检索、原文与固定版本来源一致、禁用项及撤回、预算未知、AAT 上位概念、引用快照和审批哈希。模型上下文通过模拟网关验证；这不是新提示词的真实模型效果评估。

后续最有价值的扩展：经设计师审核的本地维护/空间资料；更多逐条核实的 AAT 概念；带期望来源的中英检索题集。客观可测的指标包括检索命中率、引用准确率、约束违规率、建议接受率、完成简报所需时间。审美满意度应另做用户和设计师试验，不能拿匹配分数代替。
